# Angora Networks · r102 内部品牌与身份交付控制

**状态：仅内部准备，不联系客户、不操作设备、不追问历史订单，不重启已 PASS 事项。** 以下是未来如有经授权的新项目时可采用的记录结构，当前没有新的客户请求、排期或交付承诺。

## 一设备一记录，不混订单

| 关联字段 | 可记录的状态 / 证据 |
|---|---|
| 主体、项目与订单 | 分别保存实际客户、买方和最终使用方；名称相似、TT 型号或 Logo 不自动证明运营商采购/入网。 |
| 产品身份 | 准确 SKU、硬件修订、固件版本与哈希、许可证、生产批次；同名 SKU 不假设同端口或兼容。 |
| 标签与包装 | 区分设备铭牌、前面板、外箱、手册与图形文件；每项记录要求、样稿、明确批准、实际照片、版本与时间。缺原图则写未知。 |
| 序列号 | 按具体订单记录批准格式、单台序号、实物标签与 GUI 的比对；2024 的 `ANW` 要求和 2025 数字文书不自动合并为一条永久规则。 |
| MAC | 记录获授权地址范围、分配单位、每设备实际值、重复与冲突检测；不能从历史地址间距推定统一占用规模。 |
| 软件与操作 | 任何修改均应有授权、版本、变更记录、前后读取及回滚方案；计划远程、对话自述和现场验收分层保存。 |
| 手册与配件 | 对实际 SKU/版本核实装箱记录及配件；通用手册不替代逐箱验收，不将不同时间的聊天观察自动拼为同一缺件。 |
| 原产地及强制标识 | 真实信息和目标市场适用法律分别核验；不建议以客户偏好或品牌定制隐藏真实来源。 |

## 流程模板，仅供未来新项目采用

1. **定义**：确定设备 SKU、软硬件、语言、Logo、名称、序列号和 MAC 的项目级要求及责任人。
2. **审稿**：逐一锁定外观、界面、设备铭牌、纸箱与手册的版本，保存每次修改和明确审批；讨论中的“会提供样图”不是审批完成。
3. **验证**：在获得授权的隔离环境读取实际硬件标识、界面和测试记录；保留变更前后证据，不在生产网络擅自执行修改。
4. **交付**：按每箱记录包装和附件，按每台记录序列号/MAC；发出和接收照片、签收与验收分别留证，不假设重复型号都有新照片。
5. **合规**：经合适的法律/合规人员按目的地要求核实真实原产地及强制标识，遇疑问先停止外发承诺。
