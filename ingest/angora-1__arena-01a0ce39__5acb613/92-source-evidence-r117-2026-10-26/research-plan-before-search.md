# r117 研究计划（检索／新取文前）

## 目标与增量

以 Angora Networks 本体的早期商业史和组织方／渠道伙伴证据为中心，优先补充 2016–2022 可核的独立出版方资料；对 r116 未完整留存的科技园 2022、2024-02 两次历史回放逐块重新请求与保存。再检查 IANA PEN 公开版本史能否给出严格的历史时间锚，但绝不把 PEN 与 MAC 命名空间混同；不把标识、计划或宣传等同于实际客户交易、货物、认证或履约。

入场前先预列旧轮 33 路径并完整字节回读、SHA 与 UTF-8 解码，见 `prior-scope-before-read.csv`／`prior-read-inventory.csv`。不同来源、不同网页、不同归档和工具块保持独立文件，不重命名、不拼接；重复主体只指向既有 Angora 档案，不新建或合并客户。除非确认新证据与旧轮有矛盾，否则只写增补；若有矛盾必须在独立 dossier 附录及 mapping 中具名“修正／取代 rXX”，旧稿保留。

## 计划、获取与保真

1. 每批检索先列查询及目的，再执行；搜索响应作为发现线索而非事实证据。尽量将每次工具完整可见响应分别转存，注明人工转存并非原始 API 字节；若未留存或被截断必须明示，不能用摘要冒充原文。自动返回的 PASS 内容、停项主体或官网产品 PDF 一律不打开、引用或用于跟进。
2. 每批抓取、归档索引和 GitHub API 先列 URL、目的、请求方式；一次来源一个路径及每块独立保存。工具可见网页／索引只称 Markdown 文本抽取，逐块完整转录，有人工差错；原 HTML／图片／PDF 未取得不得标成 byte-identical。GitHub API 原响应及固定 commit 的文件字节保留 stdout／stderr／退出码，验证 blob 与 SHA-256，留失败记录。
3. 允许同一来源新的重复请求以补录，但明确新请求、动态工具栏、原请求与新请求不可混同。公开工商登记、政府机构、协会、媒体采访、厂商自述与搜索摘要评级区分；法人不明写“主体未确认”。不默认不同网页或多快照独立。
4. 用户会话截止 **2026-10-26 UTC**；新环境墙钟显示 2026-11-20，冲突未校准，不能倒填采集时间；页面正文自标、Git commit、Wayback 捕获和取文观测必须分开。10-29、10-31 自标材料在本轮截止后，不作为已发生事实。
5. 保留 INFO.rar 解压、官网评论 reCAPTCHA、48 口澄清、阶梯报价、主动下载官网 PDF 数据表、历史财务对不上的差异、未成交／未付款旧单及仓库内旧 RFQ/RFP 的永久 PASS。不访问 r104 PDF 隔离文件或 r106 官网关于页；不检索／主动接触用户叫停主体，不追问对方不愿披露的 strong partner。KBYB 三句禁区继续有效。C 档不跟进，重复主体最多联系一次。
6. 本轮被动公开研究，不发邮件、不操作设备、会议或评论区，不访问关闭的 Gmail／Drive。无新增 Ewind 事实就不变更既有分类。
7. 为回应“拉长工作时间”，持续实质工作，尽量超过 r116 的 2,124.676 秒（最终计时）；新环境 monotonic 从约 20 秒重启，虽然 boot ID 相同但不能跨环境相减；只比较本环境从入场到结束的经过时间，不用睡眠凑时。每轮保存 independent dossier 附录、mapping、单主体 follow-up、审计和严格限定的逐文件回读、哈希与测试。
