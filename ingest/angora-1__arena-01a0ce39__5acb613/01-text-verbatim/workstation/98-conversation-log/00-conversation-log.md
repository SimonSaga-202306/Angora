## 第八条：深度审计协议（核心新增）

> **设计原则**：普通总结（"通读一遍然后概括"）是有损压缩，模型会本能地"抓重点"而丢"边角信息"。 因此审计不能靠"再读一遍、再仔细一点"，而必须靠**机械化、可核对、多角色、多方法交叉**的流程。 **每次要写入 README 之前，必须完整走完以下四个阶段，不得跳步、不得合并简化。**

### 阶段一：分块处理（防止长对话注意力稀释）

- 若本次对话内容较长（预估超过约 3000-5000 字/轮次较多），**不得一次性通读后直接总结**。
- 按对话轮次或字符数切分为若干块（block），逐块单独提取信息，不依赖对前面内容的"印象"。
- 每一块单独输出一份提取结果，最后再合并、去重、排序。

### 阶段二：分类穷举抽取（用"穷举清单"代替"总结"）

对每一块内容，**分别、独立**回答以下问题（禁止合并成一句话概括）：

```
1️⃣ 文件/路径：本块中提到的所有文件名、路径、目录结构有哪些？（哪怕只出现一次）
2️⃣ 决策与否决：本块中做出的所有决策，以及用户明确否决/放弃的方案有哪些？
3️⃣ Bug与坑：本块中发现的所有报错信息、异常现象、边界情况有哪些？
4️⃣ 未解决事项：本块中提到但未处理完的问题、悬而未决的疑问有哪些？
5️⃣ 版本控制信息：本块中出现的所有 commit hash、分支名、tag 有哪些？
6️⃣ 关键数字与配置：本块中提到的所有具体数值、参数、环境变量名（不含密钥值）有哪些？
7️⃣ 用户明确要求/偏好：用户在本块中提出的、未必是"任务"但属于"要求"的内容有哪些？
   （例如："以后不要用 xxx 方式" "命名要遵循 yyy 规则"）
```

> 每一类必须逐条列出，不允许用"略"、"等等"、"以及其他若干"这类模糊收尾。 如某一类确实没有内容，必须明确写"本块无此类信息"，而不是留空——**留空和"确认无"是两种不同状态，必须区分**。

### 阶段三：锚点机械核对（不依赖模型"理解"，靠字符串比对）

1. 从原始对话全文中，机械提取（可用 grep/正则思路）所有**专有名词**：
    - 文件名、函数名、类名
    - 错误信息关键片段
    - commit hash（长度特征明显）
    - 分支名
    - 用户提到的具体人名/项目名/服务名
2. 逐一核对：这个词是否已经出现在即将写入 README 的内容里？
3. 未出现的，回头判断是否需要补充；补充后重新核对一次，直到清单清零或明确标注"无需记录"（并写明原因）。

**输出格式：**

```
🔍 锚点核对表
| 专有名词 | 类型 | 是否已入 README | 备注 |
|---------|------|-----------------|------|
| xxx.py  | 文件 | ✅ 已记录         |      |
| abc123  | commit | ❌ 未记录       | 需补充 |
```

### 阶段四：角色分离交叉检查（防止确认偏误）

- **写手角色**：完成 README 更新草稿。
    
- **审计员角色**（同一 Agent，但必须显式切换视角，假装"没看过写手的思考过程"）：
    
    - 只对比"原始对话全文" vs "写手产出的 README 更新草稿"
    - 只回答一个问题："原始对话里有、README 草稿里没有的信息点是什么？"
    - **不做总结、不做润色、只做差异发现**
- **逆向复述校验（往返测试）**：
    
    - 审计员**只看 README 草稿，不看原对话**，尝试复述"这次对话大概发生了什么"
    - 将这份复述与原始对话做比对：
        - 复述中出现了原对话没有的内容 → 说明 README 有编造/推断成分，需修正
        - 复述中缺失了原对话有的关键内容 → 说明 README 有遗漏，需补充
    - 这一步专门用于捕捉"正向审计容易漏掉"的系统性盲区

### 阶段五：抽样复核（固定锚点，而非随机凭感觉）

不要"随便抽查几段"，而要固定在以下位置抽查，形成可重复的检查习惯：

- 对话**开头 10%**片段
- 对话**中间 50%**片段
- 对话**结尾 10%**片段
- 以及：**上一轮 Agent 交接时特别强调过的内容**（如有）

对每个抽查片段，重新走一遍"阶段二的分类穷举"，并核对结果是否已体现在 README 中。

### 阶段六：输出审计报告（每次更新 README 后必须附带）

```
📊 深度审计报告
✅ 已确认覆盖的信息点（按类别列出）：
   - 文件/路径：...
   - 决策：...
   - Bug/坑：...
   - 未解决事项：...
   - 版本信息：...

⚠️ 审计中发现并已补充的遗漏项：
   - <具体内容> → 已补充至 README 的 <字段名>

❓ 不确定是否需要记录、需要用户判断的信息：
   - <具体内容，说明为何不确定>

🔁 本次审计使用的方法：
   - [x] 分块处理  [x] 分类穷举  [x] 锚点核对
   - [x] 角色分离交叉检查  [x] 逆向复述校验  [x] 固定位置抽样复核

🧮 覆盖率自估：本次对话预估信息点共 <N> 项，已确认记录 <M> 项，
    未确认/待用户判断 <K> 项。
```

> **只有输出了完整的审计报告，本轮 README 更新才算完成。缺少审计报告的更新视为无效更新，需要重做。**
