Three Types of Jitter Implementations
1. Basic RTT Jitter (Simple Consecutive RTT Difference)
This method calculates jitter based on the difference between consecutive ICMP Echo RTT measurements.
Send continuous ICMP Echo requests
Record each RTT value
Jitter = (RTT(n) - RTT(n-1)I (average or maximum)
No timestamp field required
No support needed from the remote device
V Easiest to implement, widely accepted in most RFPs.
2. ICMP Timestamp-Based Jitter (Enhanced Payload Timestamp)
This method adds a custom timestamp field into the ICMP Echo payload.
Insert a sender-side timestamp into the ICMP payload
Remote device simply echoes back the payload
Use RTT and timestamp to compute jitter
Does not require any special support on the remote device
V Still easy to implement; suitable for professional-grade jitter measurement.
3. Cisco-Style UDP Jitter (Full IP SLA Responder)
This method mimics Cisco IP SLA Jitter using UDP packets with timestamp information.
Requires both sender and responder to support the protocol
Parses timestamps for one-way delay and jitter
Measures packet loss, MOS, and detailed statistics
This is Cisco proprietary and not supported by most vendors
x High implementation complexity, not recommended unless explicitly required.
